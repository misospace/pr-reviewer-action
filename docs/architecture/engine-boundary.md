# Review engine boundary (#726)

The review pipeline is one action-independent engine. `src/engine/review.ts` owns precheck/fingerprint interplay, context and enrichment, classification and role selection, requirements, corpus assembly, model routing/conversation/tool loop, evidence execution, deterministic enforcement, and the final structured verdict. The engine consumes a `ReviewRequest` and injected `ReviewDependencies`; it does not receive a path to `process.env` or resolve `GITHUB_*`/`INPUT_*` bindings itself.

The host remains responsible for webhook/event reception, installation auth, durable queue/state, repository clone/cache lifecycle, executor scheduling, controller HTTP API, and final forge publication orchestration. The engine is review-only: publication remains outside it.

`ReviewRequest` carries forge/repository identity, PR/head/base state, raw contract inputs, explicit ambient forge context, trigger reason, rereview intent, and optional cancellation. `ReviewDependencies` supplies workspace/run directories, platform-read capabilities, output/summary sinks, and injectable runtime hooks. The `src/run/review.ts` adapter is the Action/`run`-CLI boundary: its only job is translating runner environment and defaults into those engine contracts.

`triggerReason` and `forceRereview` are provenance only: the engine records them in the `review-request.json` artifact and cancels its own scope reason, but it does not consult them to decide anything. Rerun admission — event/fingerprint eligibility, the `ai-review` label, deduplication, supersession — stays with the host's canonical scheduling and precheck path, exactly like webhook reception and publication. A host that omits both gets an ordinary review; a host that treats them as scheduling hints must still make that decision itself.

Cancellation is fail-closed, one-directional, and propagated into the active lifecycle — not just raced. `runReviewEngine` refuses to start on an already-aborted signal, and an abort at any later point makes the run throw `RunReviewError` instead of resolving: an abort races the pipeline, is checked at every main stage boundary, and is re-checked before a result is returned, so a verdict produced after the caller cancelled can never reach a caller or publisher. The run's cancellation scope also rides every owned operation so the abandoned pipeline stops instead of running on: model requests carry it into the transport (`ChatRequestInput.signal`/`HttpCallInput.signal` tear the provider socket down and end the retry loop; a `cancelled` transport failure is never retried), platform reads bind to it through the fetch wrapper `withCancellationSignal` applied to the default adapter (a host that injects its own `PlatformReadAdapter` binds the request signal at construction), and the native tool loop's subprocesses and tool HTTP fetches bind to it via `HarnessDeps.signal`/`ToolContext.signal` (`runProcess` refuses to launch after an abort and terminates an in-flight child), as do the early-launched evidence providers (`runEvidencePhase` → `runProcess`) and the image-digest fetches (`runImageDigestPhase` → the transport deadline composed with the scope). Gate forks the run owns are aborted — and their termination awaited — before that rejection is observable, so no gate child outlives a cancelled run, and the caller's abort listener is detached on both the success and the throw path so a long-lived worker signal does not retain finished runs. With no `signal` supplied the behavior is unchanged for every existing caller.

A local host can invoke the JSON request CLI with `node dist/index.js engine --request request.json`. The request contains the `ReviewRequest` fields and explicit `workspace`, `runDir`, `outputsSink`, and optional `stepSummaryPath`/`persistArtifacts`; it never publishes. CI-gate subprocess re-entry is intentionally unavailable unless a host explicitly provides a bundle entry.

Parity policy: changes to the engine must preserve the Action adapter behavior. `tests-v3/engine.test.ts` pins Action-free engine execution, engine/adapter structured-result parity, cancellation (pre-abort refusal, mid-flight rejection of an in-flight verdict, physical teardown of the in-flight provider request, owned-gate finalization, and abort-listener detachment), edge-case artifact paths through the engine/CLI boundary (symlink escape refused, null-byte run dir fails clean), provenance redaction, and the local CLI contract alongside the existing `run.test.ts` behavior surface; `tests-v3/transport.test.ts` and `tests-v3/http-transport.test.ts` pin the transport/platform cancellation seams.

This boundary is the foundation for #725; queueing, worker lifecycle, and controller responsibilities remain external capabilities rather than duplicated reviewer logic.
