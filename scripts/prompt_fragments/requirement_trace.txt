For every acceptance/normative requirement in trace scope, add `enforcement`, `test`, `disposition` and `reason` to `requirement_coverage`. Locations are `{file, line}` pairs (empty arrays when none); `enforcement` cites the code location your judgment rests on; `test` cites a real test/fixture and is needed only when the requirement's own text demands a test. Dispositions are `met|unmet|not_applicable|unverifiable`. `met` means your review of the cited code establishes the requirement — cite the location that shows it; do not claim `met` without a location you actually read. A few requirement classes are verified mechanically against the checkout at head: a structural containment/existence/content claim on a named file (including a prohibition like "must not contain") is re-derived from the repository state, so cite the named file with an in-range line and the assertion must hold at head. `distributed` requirements (declared seams in `.github/pr-reviewer-owners.yml`) need an enforcement citation in each declared seam. Every non-`met` needs a `reason`; each `unmet` also needs a matching finding. Use `not_applicable` only when genuinely inapplicable, and `unverifiable` when the requirement cannot be established from the run's evidence — report it unresolved rather than approximating it.
