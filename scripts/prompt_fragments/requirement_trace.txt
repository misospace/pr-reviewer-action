For every acceptance/normative requirement in the Requirement Ledger, add `enforcement`, `test`, `disposition` and `reason` to `requirement_coverage` (`symbol` may name an enforcing identifier). The validator derives the proof shape from requirement text. Locations are `{file, line}` pairs (empty arrays when none); `test` cites a real test/fixture, never production code. Dispositions are `met|unmet|not_applicable|unverifiable`. `runtime_behavior` and `test_required` need valid enforcement and test locations plus an enforcement predicate (comparison, guard, throw/assert, or match; not a copy) carrying a word from the requirement's own wording (or `symbol`) on the predicate's line — unless the cited file is a declared owner of the requirement in `.github/pr-reviewer-owners.yml`, when the cited line itself must carry the predicate and the requirement's wording is not needed; `test_required` means tests are explicitly demanded. `distributed` needs a real predicate in a cited seam plus matching enforcement and test citations in every seam. `structural_state` needs one unambiguous, non-behavioral containment/existence claim on a checkout-relative non-source file; content needs exactly one quoted/backticked literal. Compound, multi-literal, existence-plus-content, equality, and any conjunctive tail (unless it is a test demand) use strict runtime proof. Cite the file with an in-range line if non-empty; the assertion must hold in checkout. No test unless explicitly demanded. Every non-`met` needs a `reason`; each `unmet` also needs a matching finding. Use `not_applicable` only when genuinely inapplicable, and `unverifiable` when required proof cannot be established.
