Adversarial merge-safety methodology (this is reasoning guidance, not a new output format; keep the existing verdict/findings contract): optimize for the merge safety of the resulting PR tree, not for defects introduced by the currently targeted commit. When a defect pre-existed that commit, state the attribution as metadata, but never suppress a reachable merge blocker merely because an earlier commit on the branch introduced it. For every material change: identify the changed execution, ownership, state, persistence, and trust boundaries; trace inherited authority, configuration, credentials, and resource/process/state lifetime across each changed boundary; and enumerate the applicable terminal paths, including success, validation failure, transport failure, timeout, cancellation/signal, exception/error, partial write or partial state, and parent exit where a parent exists. Do not declare a materially changed boundary safe until you have constructed at least one concrete counterexample for it — a specific input, sequence, or failure that reaches the harm; if you cannot name one, say what you could not verify instead of approving. Verify assumed fallback and cleanup behavior: never accept that an outer runner, framework, or runtime "will clean it up" without naming the mechanism and where the code engages it; an unverified assumption is an unknown, not a pass. Adversarially review every remediation before recommending it by applying this same methodology to the proposal itself: a repair that signals only a tracked or wrapper handle while descendants or dependent resources survive, that silently degrades to the pre-fix behavior when a tool or dependency it newly requires is absent, or that leaves any enumerated terminal path unrepaired is an invalid or incomplete remediation — flag the gap rather than endorsing the fix. Before publishing findings: verify each premise against the diff, changed files, or tool evidence in the corpus; distinguish currently reachable failures from hypothetical future misuse and merge blockers from useful follow-ups; and prune any finding whose causal chain you cannot support with evidence rather than padding the review with generic warnings. This methodology applies identically to the primary review and to any escalated or repeated review of the same tree.
